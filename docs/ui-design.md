# UI/UXデザイン

## 正本

見た目の正本はルートの `DESIGN.md`。この文書は画面構成と操作モデルだけを書く。

UI実装時は `DESIGN.md` のトークン、階層、禁止事項を優先する。ここに古い画面例が残っていても、`DESIGN.md` と矛盾する場合は `DESIGN.md` を正とする。

## 画面

| 画面               | URL         | ページタイトル                     |
| ------------------ | ----------- | ---------------------------------- |
| トップ             | `/`         | 手書きの字が、フォントになります。 |
| テンプレート       | `/template` | テンプレートを印刷する             |
| フォント作成       | `/upload`   | 撮影画像からフォントを作成する     |
| このサイトについて | `/about`    | このサイトについて                 |

リンクのラベルと遷移先のページタイトルは同じ意味にする。

## 共通構造

全ページは同じ情報構造を使う。

1. ページタイトルは `h1`。
2. セクション見出しは `h2`。
3. 本文、入力欄、チェックボックス、操作リンクは `.section__body` に入れる。
4. 見出しと本文を同じ左端に置かない。
5. 箇条書きは `ul` または `ol` を使う。
6. 操作リンクは `.act` を使う。

## トップ

トップは導線を2つに分ける。

1. `テンプレートを印刷する`: 新規に用紙を印刷する入口。
2. `撮影画像からフォントを作成する`: 撮影済み画像や既存フォントからTTFを作る入口。

`新しくフォントを作る` と `フォントを作成する` のような区別しにくい対語は使わない。

## テンプレートを印刷する

操作順にセクションを並べる。

1. フォント名を入力してください。
2. 対象文字を選んでください。
3. 印刷内容を確認してください。
4. テンプレートを印刷する。
5. 記入後に撮影へ進んでください。

`PDFをダウンロード` は、次ページへの案内より前に置く。

フォント名は任意。説明文と placeholder に同じ文言を重複させない。

## 撮影画像からフォントを作成する

入力経路は用途ごとに分けて説明する。

1. 撮影したテンプレート画像を選択する。
2. 既存フォントに文字を足す。
3. 複数ページをまとめて読み込む。

ボタンだけを横に並べない。各操作には見出し、本文、操作リンクを置く。

読み込み後の扱いは箇条書きで示す。撮影の注意も同じ見出し・本文・リスト構造で示す。

## レビュー

レビュー中は切り出した文字を `ScanResultGrid` に表示する。

- 採用、書き直し、次へは1操作で判断できるようにする。
- 書き直し対象と生成操作は出口バーに置く。
- 出口バーは review 中だけ表示する。

## このサイトについて

手順説明を重複させない。この画面はサイトの説明、対応文字、利用条件、作者、応援に絞る。

## フッター

フッターは重複導線を置かない。

1. `このサイトについて`
2. `© kako-jun`
3. build 情報がある場合だけ build 表示

作者サイトは `このサイトについて` の作者セクションに置くため、フッターには置かない。

## PWA

アプリ内の PWA install prompt は出さない。フォント作成とは別の導線になり、画面構造を乱すため。
