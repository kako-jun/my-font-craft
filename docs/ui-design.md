# UI/UXデザイン

## デザインコンセプト

**夜の机（#105）** — 夜の木製机と卓上ランプの実写背景に、枠なしの文字が浮かぶダークUI。

- 背景: 1枚の実写風写真 `public/night-desk-bg.webp`（1536x1024, WebP, 全ページ共通・固定）
- スクリム: 本文の乗る左側を暗く沈め、右のランプと紙を生かす（`.plate` / `.plate-scrim`）
- 矩形パネル・カード・枠線・ボタン枠は不使用。まとまりはインデント・余白・行間・文字サイズ差
- 操作は金の下線付きテキスト（`.act`）。hover/focus で暖色に光る
- 完了・採用・達成は「灯す」（金の光の粒 + グロー）。暗くしない
- ダーク固定。ライトテーマは作らない

トーン・色・タイポの正本は `DESIGN.md`。ここには画面構成と操作モデルを書く。

### タイポグラフィ

- 見出し・本文とも明朝系/serif（Georgia + Hiragino Mincho ProN / Yu Mincho / Noto Serif JP。Webフォント読み込みなし）
- 技術値（文字数・U+コード・%・build sha）のみ monospace（`.num`）
- コピーは動詞と名詞だけで語る。「〜しましょう」「簡単に」等の水増しコピーは書かない

## ルーティング

`@solidjs/router` によるクライアントサイドルーティング。各画面は固有 URL を持ち、リロード・直接アクセス・ブラウザ戻る/進むに自然に対応する。

| 画面                             | URL         |
| -------------------------------- | ----------- |
| Home（トップ）                   | `/`         |
| Template（PDF テンプレート印刷） | `/template` |
| Upload（スキャン + TTF 生成）    | `/upload`   |
| About                            | `/about`    |

- `App.tsx` が `<Router>` でラップし、共通レイアウト（背景プレート / Header / main / Footer）を `root` に渡す
- ホスティング側 SPA フォールバック: `public/_redirects` に `/* /index.html 200`（Cloudflare Pages）
- `fontName` は `App.tsx` の `createSignal` で保持され、ルート遷移しても消えない
- ただし `Template` / `Upload` の内部 state（Upload の phase / scanResult / glyphStatuses など）は各 page コンポーネント内で `createSignal` しているため、**他のルートに移動して戻ると失われる**。リロードでも同様
- 不明な URL は `/pages/NotFound` にフォールバック（トップへ戻るリンク付き）
- 状態の永続化（IndexedDB / sessionStorage 等）は別 Issue の範疇

## ページ構成

### 1. トップページ（#114: 読まずに流れが分かる）

```
MyFontCraft                    1. テンプレート  2. フォント作成

手書きの字が、
フォントになる。

1  テンプレートをダウンロード     ┌記入例の紙片┐
    A4のPDF。印刷して使う         │(テンプレート│
2  マスに手書き                  │ 全体 + マス │
3  撮影してアップロード           │ 拡大の2枚) │
4  フォントをダウンロード         └───────────┘

— 登録不要・無料
— 生成したフォントは個人・商用とも自由
```

- 4ステップ（数字 + 動詞句）がそのままナビゲーション: 1 → `/template`、3 → `/upload`
- 操作サンプル画像（`public/sample-template-page.webp` / `sample-filled-cells.webp`、fixtures の記入済みテンプレートから生成）を上部に常時提示
- 狭幅では記入例が先頭、ステップが下に積まれる

### 2. テンプレートページ

見出し「1. テンプレートを印刷する」。カードなしの縦一列フォーム:

- フォント名（下線のみの入力欄）
- 対象文字チェック（ひらがな 83 / カタカナ 87 / 英数字・記号 102 / 常用漢字 2,136）
- 「PDF 約Nページ」（monospace 数字）
- 記入方法1行（チェック欄は任意 — ✓ のある方を優先）
- `PDFをダウンロード`（`.act--primary`）

### 3. フォント作成ページ

見出し「2. フォントを作成する」。フェーズ: idle → scanning → review → building → done。

**idle**: ドロップゾーン（枠なし。ドラッグ中は光だまり）+ 入力ソースのテキスト操作4種 + 注意4行 + 撮影のコツ（✓/✕ 3行）

#### 入力ソース（Issue #97）

- **画像**: `<input type="file" accept="image/*" multiple>` — 複数選択可。JPEG/PNG/WebP 等
- **フォルダ**: `webkitdirectory` — 単数（フォルダ階層自由）
- **ZIP**: `accept=".zip"` — 単数
- **既存フォント**: `accept=".ttf,.otf"` — 単数

並び順: 画像 → フォルダ → ZIP → 既存フォント

**追加 / リセットの方針**:

- 入力は**常に追加（merge）**。merge 仕様は `docs/font-generation.md` 参照
- 0 文字に戻すにはドロップゾーン内「リセット（0 文字に戻す）」（`window.confirm` で確認）。リセットは review フェーズでのみ表示
- DnD で画像と ZIP / フォルダを混在投下した場合、1 回のスキャンに合流して処理される（仕様外運用だがエラーにはしない）

**scanning**: 金の細線プログレス + ページ数（monospace）

**review（#114: 紙片の検分）**: 下記「レビューの操作モデル」

**building**: 「フォントを生成中...」1行

**done**: 「フォントが完成しました」（金に灯る見出し）+ `フォントをダウンロード (.ttf)` + `最初からやり直す`

## レビューの操作モデル（#114）

概念モデル: **夜の机の上で、切り出した文字の紙片を1枚ずつランプの光で検分し、採用/書き直しを仕分ける。**

### 俯瞰（ScanResultGrid）

- 全文字が枠なしの紙片（白い紙 + 影 + ±2°の散らばり）としてページごとに並ぶ
- サマリー: 「取得 N/M 字（P%）・採用 n・書き直し m」
- 要確認セル（#110 `GlyphStatus.needsReview`）は琥珀色に明滅（`.scan-grid__cell--review`）+ `!` バッジ — **異常が先に目に入る**
- 採用済みは金の粒が灯る（`.scan-grid__cell--adopted` + `.scan-grid__cell-lit`）
- 書き直しは影に沈み琥珀の ✕（`.scan-grid__cell--excluded`）
- 未検出は紙片なし。文字の薄いゴーストのみ
- ページサムネイル（補正後画像）クリックでライトボックス拡大

### 検分（inspector）

- 紙片をクリック/タップ（または俯瞰で ← →）で開く。ランプの光だまりの中に1枚を大きく表示
- `←` `→` キー / スワイプで前後の紙片へ。マウス精密操作は不要
- メタ表示: 文字・U+コード・現在の仕分け（未仕分け / 採用 — 灯 / 書き直し / 空）・要確認フラグ

### 仕分け（3値のみ）

| 判定     | キー    | タップ       | 効果                                            |
| -------- | ------- | ------------ | ----------------------------------------------- |
| 採用     | `Enter` | 「採用」     | 灯る（金の粒）。書き直しからの復帰も兼ねる      |
| 書き直し | `X`     | 「書き直し」 | リトライ対象へ（フォントから除外）              |
| 次へ     | `Space` | 「次へ」     | 仕分けせず次の紙片へ（未仕分け=生成対象のまま） |

- 1キー / 1タップで確定して自動的に次の紙片へ。最後の1枚で仕分けると検分終了
- `Esc` で俯瞰に戻る
- 未仕分けの取得文字は生成対象（採用は「確認した」の灯り）

### 出口（常に見える）

review 中は画面下に固定の出口バー（`.exit-bar`、パネルではなくスクリム）:

- 「書き直し N 字 → リトライPDF」（現在 disabled — リトライPDFは v:3 QR の `s` フラグ未対応のため調整中、Issue #96）
- 「このまま生成する（M 文字）」/ 全文字取得済みなら「フォントを生成する」

## PWA インストール促し（#124）

`beforeinstallprompt` 発火時のみ、ヘッダーの直前に通常フローで挿入される帯（`.install-bar`）で「ホーム画面に追加すると、次からすぐ開ける」を表示する。

- `position: fixed` にしない。ヘッダーは `position` 未指定のためオーバーレイにすると常にバナーの下に沈む（positioned 要素は z-index に関わらず非 positioned 要素より後に描画される）。通常フロー挿入なら表示中はヘッダーが自然にバナー分だけ下へ押し出されるだけなので、ヘッダー（ロゴ・ナビ）を覆い隠すことがない
- 背景を持たないパネル化しないバー: 文言は `.message--info` を流用（`·` マーク + `ink-dim`）。操作は `.act`（追加する）/ `.act--quiet`（閉じる）
- 既にインストール済み（`display-mode: standalone`）なら出さない
- 「閉じる」を押すと localStorage に記憶し、以後再表示しない（mypace の7日後再表示は採用せず、恒久非表示にする意図的な簡略化）
- 出口バー（画面下部・review 中のみのオーバーレイ）とは配置方式自体が異なり干渉しない
- **既知の制約**: このリポには Service Worker が無い。Chrome のインストール可能性判定はバージョンによって fetch ハンドラ付き SW の登録を条件に含む場合があり、その場合 `beforeinstallprompt` 自体が発火しない可能性がある。発火するかは実機確認が必要（SW 導入は別スコープ）

## レスポンシブ対応

| 画面幅                | 対応                                                                 |
| --------------------- | -------------------------------------------------------------------- |
| > 860px               | 本文カラム左寄せ（46rem）。右にランプと紙の写真が見える              |
| 720–860px             | Home の記入例がステップの上へ                                        |
| < 720px（390px 含む） | 1カラム。背景は暗い木目側（38% 50%）+ 濃いスクリム。横スクロールなし |

- 紙片グリッドは `minmax(46-52px, 1fr)`。タッチターゲット 44px 以上
- 検分の仕分けはタップ、移動はスワイプ
- 出口バーは折り返し。review 中は本文下部に余白（`.upload-page--review`）

## アクセシビリティ

- コントラスト比: 本文 `ink` / 背景暗部で 4.5:1 以上（スクリム + text-shadow で担保）
- キーボード完結: 俯瞰セルは tabIndex + Enter/Space で検分を開き、検分内は Enter / X / Space / ← → / Esc
- 検分ビューは `role="dialog"` + `aria-modal`。開いたらフォーカスを移す
- `:focus-visible` に金のアウトライン
- `prefers-reduced-motion: reduce` で明滅・トランジション全停止
- 画像には alt（記入例・紙片は文字名）
