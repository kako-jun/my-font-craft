# 画像処理仕様

## 入力要件

| 項目               | 要件                                                 |
| ------------------ | ---------------------------------------------------- |
| 対応形式           | JPEG, PNG, WebP（HEICはSafariのみ対応）              |
| 推奨解像度         | 300dpi以上                                           |
| 最小解像度         | 150dpi（警告表示）                                   |
| 最大ファイルサイズ | 50MB/枚                                              |
| 入力方法           | フォルダ選択 or ZIPファイル（ドラッグ&ドロップ対応） |
| ファイル名規則     | 任意（QRコードでページ識別。フォルダ階層も自由）     |

**ユーザーによる事前補正は不要**。スキャナーでもスマホ撮影でも対応。
ZIP内の `__MACOSX/` や `._*` メタファイルは自動除外。

## 処理フロー

```
1. 画像読み込み（Exif Orientation を読んで自動回転）
      ↓
2. 中心マーカー事前検出（アンカー） → 四隅マーカー検出 → 向き検出・回転補正 → DPI算出（マーカー間距離、150未満でエラー） → 台形補正（反復収束）
      ↓
2.4. 中心マーカー検証 → 残差>1mm なら 9点TPS（4隅+4辺中点+中心）でレンズ歪み補正
      ↓
2.5. 微小角度デスキュー（TPS未適用時のみ、罫線から残留回転を検出・補正、0.05°〜5°）
      ↓
3. QRコード読み取り → ページ識別（補正後の画像から読む）
      ↓ （読めない場合はエラー）
3.5. ホワイトバランス補正（グレースケールバー最明部から色温度正規化）
      ↓
4. 左右縦グレースケールバー読み取り → 影勾配補正
      ↓
5. シアンサンプル読み取り → 除去閾値決定
      ↓
6. シアン色の除去
      ↓
7. 各マス切り出し（47文字 × 2マス = 94マス、中心マーカー分を除く）
      ↓
8. 文字ごとに（2マスをペアで処理）:
   - モアレ検出・除去（ラプラシアン分散検出 → 3×3メディアンフィルタ、スキャナー使用時のみ）
   - CLAHE（ローカルコントラスト正規化、4×4タイル、クリッピング3.0）
   - Sauvola適応的二値化（局所ウィンドウ15×15、k=0.2）
   - モルフォロジカルノイズ除去（Opening→Closing、3×3カーネル）
   - セル品質ゲート（#110: 連結成分分析で境界接触残渣を除去 + 面積フィルタ + needs_review 判定）
   - インクブリード補正（3×3 erosion 1回、黒率50%未満になる場合はスキップ）
   - 各マスの空判定（内側60%で黒2%未満=空）
   - 各マスのチェック欄解析（✓/空欄）
   - 採用判定（template-spec.md の判定フローに従う）
      ↓
9. 採用マスの文字をベクター化
      ↓
10. ランレングス抽出 → ベクター化
      ↓
11. グリフとして登録
```

## 台形補正

### 四隅マーカー検出

1. 画像を二値化
2. 中心マーカーを事前検出（`detect_center_marker`）— 検出できれば `center_hint` として四隅クアッド選定のアンカーに使う。未検出でもフォールバックで動作する（#132）
3. 連結成分解析で四隅それぞれの探索領域（25%マージン）内のブロブを検出し、コーナー近さ順に distinct クラスタ最大 `CORNER_CANDIDATE_K`=30 件を候補化する（同一クラスタに属するブロブはマージして1候補に数える、#132）。4隅とも上限近くまで候補が生存すると総組み合わせ数（4隅の積）が最大 30⁴=810,000 通りになりうるため、`COMBO_EXPLOSION_THRESHOLD`=100,000 を超えたら各隅を近さ上位 `COMBO_TRUNCATE_K`=10 件に切り詰める（黙って打ち切らずログに残す、#132フォローアップ）
4. 各候補を2段のゲートで足切りする。落ちても即エラーにはせず次点候補に回す:
   - **候補足切りゲート（#115）**: 外接矩形の形状検証（縦横比 0.6〜1.667・大きさ 0.45〜2.5×marker_px の帯で細長片・巨大/微小ブロブを除外。透視不変なので傾いた実写は誤棄却しない）。#132 で「クアッド全体を棄却する致命エラー」から「候補ごとの足切りゲート」に降格した
   - **紙白アニュラスゲート（#132・本命の防御）**: 候補周囲の環状領域（半径 marker_px/2 の 1.3〜1.8 倍）で、二値化白（紙background）の比率が 0.5 未満なら棄却。紙の上のマーカーは周囲が紙白、木目の節や机の縁は周囲も暗色・中間調が続くため分離できる。木目の机で撮影した実写真で紙外ブロブを誤検出した事故（#132）を踏まえて追加した防御
5. 生き残った候補のブロブ重心（ピクセル加重平均）→ パラボリック補間でサブピクセル精度に精緻化
6. 隅ごとに生き残った候補の全組み合わせをクアッド幾何ゲート＋スコアリングで評価し、最良の1組を採用する（#132）:
   - **クアッド幾何ゲート**: 組み上げた4点が妥当な矩形か（対辺比 0.6〜1.667＝〜30°の傾きまで許容・テンプレート既知アスペクト≈0.697との照合・非退化/点入れ替わりの符号付き面積チェック）。粗い破綻のみ捕捉するサニティ
   - **スコア**（小さいほど良い、4項の和）: (1) アスペクト比偏差、(2) 対辺長比偏差、(3) **サイズ整合偏差**（クアッド辺長とマーカーブロブ自身の外接矩形サイズの比を、レイアウト既知の期待比＝マーカー中心間隔/MARKER_SIZE と比較した偏差。透視は辺長とマーカー径を一次近似で同率に縮めるため透視に頑健。「マーカーサイズはそのまま辺長だけ縮む」同心縮小デコイを排除する目的で追加。重み `SCORE_WEIGHT_SIZE_CONSISTENCY`=0.05 — 実写真のリングマーカーは複数ブロブの merge で bbox が理論値の1.5〜2倍に膨らむことがあり、それが正しい候補であるケースもあるため、大きな重みは実写真で誤判定を招く。center 項だけでは僅差すぎる局面のタイブレークとして働く程度に小さく抑えている、#132フォローアップ）、(4) **中心マーカー整合**（クアッド対角線交点と事前検出した中心マーカーの距離を対角線長で正規化した値、重み8＝4項中もっとも支配的）。中心マーカー未検出時は (4) を除外
   - 全組み合わせがクアッド幾何ゲートで棄却された場合のみエラー（メッセージは従来と互換）
7. 4点の座標を取得
8. 射影変換（Perspective Transform）で長方形に補正

### 台形補正の反復収束

初回ホモグラフィー適用後、補正品質を検証して必要なら補正し直す（最大3回）:

1. 補正後画像でマーカーを再検出し、layout の期待位置（mm→px）との残差を測る
2. 最大残差が `residual_threshold_mm`=1.0mm 以下なら収束として打ち切り
3. 超えていれば、再検出した4点を使って再ホモグラフィー（`homography_refine`）を計算し、補正をやり直す
4. 3回で収束しなくても処理は継続する（警告ログのみ。以降の中心マーカー検証・TPS判定で状況次第では撮り直しを促すエラーに発展しうる）
5. 再検出そのものに失敗した場合は反復を中断する（それまでの補正結果のまま続行）

この反復で使うマーカー再検出は、初回検出（`detect_markers`、上記）ではなく後述の局所探索版（`detect_markers_near_expected`）を使う。

### 補正後の再検出（局所探索、#132フォローアップ）

初回検出（上記）とは別に、補正後の画像に対しては 2 箇所でマーカーを再検出する:

- **台形補正の反復収束**（上記）: 各反復で補正後画像を再検出し、期待位置との残差を測る
- **TPS レンズ歪み補正**（後述）: 4隅を再検出して制御点に加える

補正後画像では4隅の期待位置が layout の mm 座標から既知なので、初回検出と同じ「25%マージン領域の全域探索＋組み合わせスコアリング」は不要かつ有害になりうる（全域探索のままだと、紙外に残った誤検出クラスタに再び引っ張られることがあった）。そのため `detect_markers_near_expected` という別関数を使う:

1. 各マーカーについて、期待中心を中心とする一辺 `2 × LOCAL_SEARCH_RADIUS_RATIO(=2.5) × marker_px` の窓だけでブロブ抽出（較正: 実写真2枚 + wood-background フィクスチャ）
2. 形状ゲート（#115）を通過した候補のうち期待位置に最も近いものを採用
3. 紙白アニュラスゲートは適用しない — 窓が画像端（紙の外）にかかると外側リングが紙外領域を含んで誤爆しうるため。窓を期待位置近傍だけに絞ること自体が誤検出排除の防御として機能する
4. 窓内に候補が無ければ Err（呼び出し側は「反復中断」または「TPSスキップ」で graceful に扱う。エラー文言契約は変えていない）

### 向き検出

- 左上マーカーのみ塗りつぶし（★）
- 他は白抜き（☆）
- 黒ピクセル密度方式で塗りつぶしマーカーを判定（影に強い）（0°/90°/180°/270°）

### Exif Orientation 自動適用

スマホ撮影画像（特に Android 縦撮影）では、画像本体ではなく Exif の Orientation タグに回転情報が記録される。`image::open()` / `image::load_from_memory()` はこれを自動適用しないため、`ImageReader::into_decoder()` 経由で `ImageDecoder::orientation()` を取得し `DynamicImage::apply_orientation()` で明示適用する。CLI/WASM 両パスで対応。

### レンズ歪み補正（9点TPS / Thin Plate Spline）

台形補正（4点ホモグラフィー）は平面の射影変換まではきれいに復元できるが、カメラレンズの樽型／糸巻き型歪み（特にスマホの広角＋近接撮影）で紙面の中央が膨らむケースは扱えない。中心マーカーを5点目の制御点として加え、TPS で再ワープする。

#### アルゴリズム

1. ホモグラフィー収束後の画像から中心マーカーを再検出
2. 期待位置との残差（mm）を算出。1.0mm 以下ならスキップ（過補正のリスク回避）
3. 4隅マーカーを再検出して制御点に加える（局所探索版 `detect_markers_near_expected` を使用。「補正後の再検出」参照。失敗時は TPS 補正をスキップして補正後画像をそのまま返す graceful fallback）
4. 4辺中点を「ホモグラフィー後は紙面の辺が直線として保たれる」前提で `mid(corner_src) → mid(corner_dst)` として制御点に追加（境界をアンカーして TPS の引き戻しを内部だけに限定）
5. 9点（4隅 + 4辺中点 + 中心）で TPS をフィットし、各 dst ピクセルに対して src サンプリング座標を算出して再描画
6. TPS適用後は中心残差をログに残す

TPS は dst→src 方向で N=9 の線形系（12×12）を x/y 独立に解く。基底関数は U(r²) = r² ln(r²)。

#### 発動条件と制限

中心残差の扱いは4段階:

- 残差 ≤ `TPS_MIN_RESIDUAL_MM (= 1.0)` mm: TPS スキップ。ホモグラフィー単体で十分な精度。
- `1.0 < 残差 ≤ LENS_DISTORTION_WARN_MM (= 5.0)` mm: 9点TPS を適用して歪みを吸収（無警告）。
- `5.0 < 残差 ≤ SEVERE_LENS_DISTORTION_MM (= 10.0)` mm: 9点TPS を適用するが、紙端の精度低下を警告ログに残す。スマホ広角撮影で現実的に発生する範囲。
- 残差 > 10.0 mm: **パイプラインをエラーで中断**。9点では境界の樽型歪みを吸収しきれないため、「もう一歩離れて撮り直してください」というメッセージをユーザーに返す。

理由は「ホモグラフィー後の紙面の辺は直線」という前提で 4辺中点を src=dst でアンカーしているため、実際にはレンズ歪みで辺自体が湾曲している重度ケースではこの仮定が破れて境界付近が歪んで残る。Issue #88/#92 の方針で「グリッド交点を制御点に追加する高密度TPS」を入れれば許容を上げられるが、現時点では撮り直し誘導が実用的。

### 微小角度デスキュー

台形補正後に残る1〜3°程度の微小回転を検出・補正する。**TPS適用時はスキップ** — 中心軸まわりの微小回転を加えると、TPS で厳密に合わせた端部マーカーがズレてレイアウト前提を壊すため。

#### アルゴリズム

1. 台形補正後の画像を二値化し、格子線（縦罫線）の位置をスキャン
2. 各縦罫線について上端と下端のX座標を検出し、傾き角度を算出
3. 全罫線の角度の中央値を残留回転角度とする
4. 画像中心を基準にアフィン回転（バイリニア補間）で補正

#### 閾値

- 0.05°未満: 補正不要（精度の範囲内）
- 0.05°〜5°: 微小回転補正を適用
- 5°超: 台形補正自体が失敗している可能性があるため警告ログを出力（補正は試行する）

## 色補正

### ホワイトバランス補正（色温度正規化）

スマホ撮影時の照明の色温度により紙が黄色・青味を帯びる問題を補正する。Von Kries chromatic adaptation の簡易版。

#### アルゴリズム

1. グレースケールバーの上位3ステップ（ステップ7,8,9）の左右バーからRGB各チャネルの平均値をサンプリング。複数ステップを使うことでノイズや局所的な影の影響を低減
2. 各ステップの期待値と実測値から補正係数を算出し、3ステップの平均を最終係数とする: `(期待値/R_avg, 期待値/G_avg, 期待値/B_avg)`
3. 全ピクセルに乗算補正 + 0-255クランプ
4. 補正係数が極端な場合（0.5未満 or 2.0超）は異常とみなしスキップ

#### 処理順序

台形補正後・影補正前に実行する。色温度バイアスは位置非依存なので影補正（位置依存）より先に除去することで、後段の影補正・シアン除去の精度が向上する。

### 左右縦グレースケールバーによる影勾配補正

ページ左右に配置された縦グレースケールバー（10段階、上:黒→下:白）を読み取り、スキャン時の影勾配を補正する。

#### アルゴリズム

1. 左右バーの各ステップ（10段階）の中央部分をサンプリングし、平均輝度を取得
2. 各ステップの期待値（0, 25.5, 51, ... 229.5）との差分（delta）を計算
3. 画像の各ピクセルに対して:
   - Y方向: バーのどのステップに該当するかを線形補間で決定
   - X方向: 左バーと右バーのdelta値を線形補間
   - 補間した補正量をRGB各チャンネルから減算

#### 効果

- **上下方向の影**: スキャナーの光源ムラ、スマホ撮影時の上下照度差を補正
- **左右方向の影**: 本の綴じ部分の影、斜め照明による左右の明暗差を補正
- バー外側の領域はクランプされるため、バー範囲外でも自然に補正が適用される

#### 処理順序

台形補正後・シアン除去前に実行する。影補正をシアン除去より先に行うことで、影によるシアン色の変化も考慮した除去が可能になる。

### シアン除去

1. シアンサンプル領域（座標既知）の平均RGBを取得
2. サンプルの cyan-score（`min(G, B) - R`）が 1.5 未満ならスキップ（サンプルにシアン成分なし）
3. 画像全体の各ピクセルについて、輝度 ≥ 140 かつ cyan-score ≥ 3 なら白(#FFFFFF)に置換

薄シアン（#E6FFFF 程度）の印刷にも対応するため、固定RGB距離ではなく cyan-signature ベースで判定する。黒ペン（彩度ゼロ）は cyan-score ≈ 0 で自然に保護される。色検出に失敗した場合でも、後段の `erase_grid_lines` が layout 既知の内枠座標を白塗りするため致命的な問題にはならない。

### 紙白正規化

シアン除去後、罫線残骸除去前に実行する。輝度ヒストグラムの 100 以上の範囲で最頻値（= 紙の地色）を見つけ、それを 255 にスケーリング。shadow_correct 後も紙が灰色のまま残ると Sauvola 二値化がノイズを拾うため、事前に純白へ寄せる。

### 罫線残骸除去

layout 既知の外枠・内枠・**ガイド線（#111）**・チェック欄・見本文字枠・グレースケールバー境界を、台形補正の残差を吸収するマージン（外枠 ±6px、内枠 ±5px、ガイド線 ±4px）で白塗りする。外枠を広めに取っているのは、TPS 後の残差ズレ（数px）で外枠の消し残しが出るケースがあったため（#34）。6px = 0.5mm@300dpi なので手書きへの影響は実質ゼロ。

**条件付き白塗り**: ピクセルの輝度が 150 未満（= 黒インク相当）の場合は白塗りをスキップする。これにより、内枠線・ガイド線を跨ぐ手書きストロークが途切れる問題を防ぐ。シアン枠は輝度が高いので従来通り除去される。

### ガイド線除去の防御層（#111）

テンプレートのベースライン/センターガイド線（シアン、書く領域の内側を横切る）が
グリフに混入しないための防御層と、その実態:

| 層  | 処理                                 | 役割・実態                                                                                                                                                                          |
| --- | ------------------------------------ | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 1   | シアン除去（色ベース）               | **主防御**。ガイド線はシアンなので色検出で消える。モノクロ印刷では薄グレー印字になり無力化する                                                                                      |
| 2   | 罫線残骸除去（layout 既知の白塗り）  | **第2防御**。色検出に失敗しても、既知座標 ±4px を条件付き白塗り。ただし輝度150未満は手書き保護でスキップするため、濃いモノクロ印字は L1 と同時に素通りし得る                        |
| 3   | セル品質ゲート（#110、境界接触除去） | **ガイド線に対しては原理的に不発**。ガイド線はセル中央付近を横切り、線の端点（内枠端）でも crop 境界から約 1mm ≈ 11.8px 離れているため、境界帯（2px）接触の判定には決して掛からない |

このほか、Sauvola 二値化が明るい残存線（薄シアンは輝度 ≈248）を黒と拾いにくい
という**暗黙のフィルタ**も実際には働くが、CLAHE の局所コントラスト強調や影条件
次第で黒化しうるため、防御層としては数えない。

つまりガイド線は「シアン除去が主防御・罫線残骸除去が第2防御」で消す設計であり、
品質ゲートに頼ってはいけない（枠・罫線残渣とは侵入経路が違う）。L1/L2 を同時に
すり抜けた場合（典型: モノクロ印刷）は太い水平線がグリフに混入し、needs_review も
立たない — この挙動は `cli/src/vectorizer.rs` の
`guide_line_surviving_binarization_becomes_paths_without_review` テストで
現状仕様として固定している。実質的な検知器は**シアンサンプル未検出の UI 警告**:
`remove_cyan` が sample_score < 1.5 で検出フラグ false を返し、scanner が
`[scan:cyan]` warning ログと「テンプレートがカラー印刷されているか確認してください」
警告を UI に出す（#111 QA）。

## マス切り出し

### 座標計算

テンプレート仕様に基づき、各マスの座標を計算：

```typescript
const MARGIN = 10; // mm
const HEADER_HEIGHT = 7; // mm
const MARKER_SIZE = 8; // mm
const BODY_START_Y = 28; // MARGIN + HEADER_HEIGHT + MARKER_SIZE + 余白3
const COL_WIDTH = 47; // mm
const ROW_HEIGHT = 20; // mm
const SAMPLE_WIDTH = 10; // mm
const CELL_SIZE = 15; // mm
const CELL_GAP = 2; // mm

function getCellPosition(row: number, col: number, cellIndex: number) {
  const x = MARGIN + col * COL_WIDTH + SAMPLE_WIDTH + CELL_GAP + cellIndex * (CELL_SIZE + CELL_GAP);
  const y = BODY_START_Y + row * ROW_HEIGHT;
  return { x, y };
}
```

## チェック欄解析

### AI使用方針

| 用途             | AI使用      | 理由                     |
| ---------------- | ----------- | ------------------------ |
| 文字の補間・生成 | ❌ 使わない | 本人の字を100%使用が必須 |
| ✓印の検出        | ✅ 使う     | 手書きの揺らぎに対応     |
| 空マスの検出     | ✅ 使う     | ノイズと記入の区別       |

### 実装方針（Phase別）

**Phase 1（MVP）**: テンプレートマッチング

- 開発コストが低い
- 精度は十分
- ブラウザで動作可能

**Phase 2（将来）**: 画像分類（機械学習）

- より高精度
- TensorFlow.jsで実装可能

### 空マス検出の閾値

- 内枠領域（INNER_SIZE=10mm）の内側60%で黒ピクセルが**2%未満** → 空マスと判定（外周20%は格子線残骸を除外）
- ノイズ除去: 連続した黒領域が**10ピクセル未満**は無視

### ✓の検出手順

1. チェック欄（3mm高さ）を切り出し
2. CLAHE（ローカルコントラスト正規化）
3. Sauvola適応的二値化（k=0.2、ウィンドウ15×15）
4. モルフォロジカルノイズ除去（Opening→Closing、3×3カーネル）
5. 黒ピクセル密度で判定:
   - 密度 < 2% → 空欄
   - 密度 >= 2% → ✓

## セル品質ゲート（#110）

上流の除去処理（シアン除去・罫線残骸除去・影補正）が残渣を1pxでも取りこぼすと、
そのままグリフ形状に混入してしまう。上流を完璧にする軍拡競争から降りるため、
**ベクター化直前の二値化セル画像**に下流の防御層として連結成分分析ゲートを置く。

### 処理順序

```
グレー化 → CLAHE → Sauvola二値化 → モルフォロジ Opening→Closing
  → 品質ゲート（境界接触成分の除去 + 面積フィルタ）
  → インクブリード補正（1px erosion） → ベクター化
```

ゲートをインクブリード補正より**前**に置くのは、erosion で残渣の境界接触が
1px 後退して検出帯から外れるのを防ぐため。プレビュー画像（review UI のセル表示）と
ベクター化は同じゲート済みバイナリを使うため、見た目と出力が常に一致する。

### アルゴリズム（`cli/src/cell.rs::apply_cell_quality_gate`）

8近傍ラベリングで黒連結成分を列挙し、成分ごとに判定する。

1. **境界接触成分の除去** — セル外周 **2px 帯**に触れる成分は枠・罫線残渣とみなして白に倒す。
   枠・罫線残渣は必ずセル境界から侵入し、ストロークは切り出しマージン（1.5mm）により
   境界に接触しない前提。帯が 1px でなく 2px なのは、モルフォロジ Closing の最終 Erosion が
   「画像外=白」扱いのため最外周 1px が常に白になり、残渣は必ず 2px 目以降に残るから。
   **既知の限界**: TPS 補正残差（0.5〜1mm ≈ 6〜12px）で残渣が帯の外側へずれて写った場合は
   境界接触にならずゲートを素通りする（対応は #113 のスコープ）
2. **はみ出しストローク保護（安全弁）** — 境界接触でも「面積比 ≥ 4% かつ bbox 短辺 > 3px」の
   成分は、はみ出して書いた字の可能性があるため**除去せず** needs_review だけ立てる
   （字が丸ごと消えるのが最悪の退行）。残渣は細線（bbox 短辺 ≤ 3px）または
   小面積（< 4%）なのでこの保護には掛からない。
   帯内でも面積 < 10px の微小成分はスペックノイズ扱いに降格して除去し、それ単独では
   needs_review を立てない（エッジのダストでセルが警告になる偽陽性を防ぐ）
3. **面積フィルタ** — 境界に触れない成分でも面積 < 10px はスペックノイズとして除去
   （空判定用 `remove_small_black_components` のベクター化経路への一般化）

### needs_review（要確認フラグ）

除去は黙って行わず、以下のいずれかで `needs_review` を立てて review UI に
「要確認」（警告色の枠 + セル右上の `!` バッジ）として見せる。

| 条件                         | 意図                                               |
| ---------------------------- | -------------------------------------------------- |
| 境界接触除去が発生した       | 残渣を消した = 上流で何かをすり抜けている          |
| はみ出しストロークを保護した | 消さなかったが異常な形なので目視確認               |
| 除去面積比 > 1%              | まとまった量の除去（内側スペックの日常除去は除く） |
| 除去の結果 残成分がゼロ化    | 空グリフに倒れた（黙って空にしない）               |

品質情報（`removed_components` / `removed_area_ratio` / `kept_components` /
`ink_ratio` / `needs_review`）は WASM 出力の各セル（`ProcessedCell.quality`）に載り、
scanner の段階ログ `[scan:cells] ... review=N` と review UI に伝搬する。

## ベクター化

### アルゴリズム

1. **二値化**（Sauvola 適応的二値化 + CLAHE + モルフォロジ open-close + セル品質ゲート）
2. **2x アップスケール**（nearest neighbor）— ドットを細粒化してギザギザを目立ちにくくする
3. **ランレングス抽出** — 各行の黒ピクセル連続区間（ラン）を検出
4. **縦方向マージ** — 隣接行で x 範囲が ±2px 以内のランを結合して矩形にまとめ、パス数を削減
5. **フォント座標変換** — 各矩形を四角形パス（M→L→L→L→Z）に変換

二値化画像と100%同じ見た目が保証される。拡大時は水平方向は滑らか、垂直方向にのみ階段状のギザギザが出る。

### フォント座標への変換（セル→em 固定変換、#111）

bbox 正規化は廃止した。セル crop（12mm 四方）を固定アフィン変換で em 座標に写す:
内枠（10mm、書く領域）= em-square [0, 1000] × [-120, 880]、1mm = 100 units。
書いた位置・大きさがそのままフォントに出る（句読点は左下に小さく、descender は
y<0 へ）。座標系の正本は [docs/font-generation.md](./font-generation.md) の
「グリフ配置」を参照。旧 bbox 正規化は opt-in の救済
（`vectorize_binary_bbox_fit`、既定 OFF）として判断ロジックのみ残る。

## パフォーマンス目標

| 処理                     | 目標時間 | 根拠                               |
| ------------------------ | -------- | ---------------------------------- |
| 画像処理（1ページ）      | 2秒以内  | ユーザーが進捗を体感できる最小単位 |
| 全ページ処理（51ページ） | 2分以内  | Webアプリの許容待機時間（5分未満） |
| フォント生成             | 10秒以内 | 処理完了の即時フィードバック       |

### 根拠

- **2秒/ページ**: プログレスバーが定期的に動くことでユーザーの離脱を防止
- **3分以内**: 研究によるとWebアプリの待機許容時間は3〜5分程度
- **10秒以内**: 最終処理は短くして達成感を演出

※ 実際のベンチマークで調整予定

## ユーザーフロー（3フェーズ）

```
Phase 1: スキャン
  画像アップロード → マーカー/QR/シアン処理 → セル切出し → ベクター化
  → 結果をグリッドに表示（ページ単位→文字単位の2階層）

Phase 2: 確認（レビュー）
  グリッド上で取得/未検出/インポート済みを確認
  ├── 全文字取得 → Phase 3 へ
  ├── 未検出あり → リトライ用テンプレートPDFダウンロード
  │    → 書き直し → 追加スキャン → 既存結果にマージ → 再確認
  ├── 既存フォントをインポート → 未検出分をインポートで穴埋め
  └── そのまま生成 → Phase 3 へ（未検出文字はフォントに含まれない）

Phase 3: フォント生成
  ユーザーがボタンを押して明示的に実行 → .ttf ダウンロード
```

### リトライ用テンプレートPDF

未検出文字のみを集めた小規模テンプレート（例: 6文字なら1ページ）を生成。
51ページ全体の再印刷を不要にする。

### 追加スキャンのマージ

レビュー中に追加画像をアップロードすると、既存結果を保持したまま
新しく取得できた文字で未検出分を差分マージする。

### 段階診断ログ

スキャン失敗時にどの段階で落ちたか console から判別できる。

- TS 側（`src/lib/scanner/processor.ts`）: `[scan:{stage}] ...` 形式。stage は `pipeline` / `marker` / `dpi` / `perspective` / `decode` / `qr` / `cyan`（シアンサンプル未検出の warning、#111） / `chars` / `cells` / `vectorize` / `font-input`、および文言から段階を推定できない WASM エラーのフォールバック `wasm`。WASM エラーはエラー文言から失敗段階を推定する（`inferFailedStage`）。ログレベルは info / warn / error の3段階
- WASM 側（Rust `log!`）: `=== ステップN: ... ===` 形式で内部段階（二値化・マーカー検出・ホモグラフィー・QR・セル切り出し等）を出力
- e2e は `page.on('console')` で両方を収集し、テスト失敗時に添付（`scan-stage-logs`）+ コンソール出力する
